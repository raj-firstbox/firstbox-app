# Firstbox app

Internal software for Firstbox (custom rigid boxes, mono cartons, printing). Owner: Raj Wadhwa, who is not a programmer:
explain changes in plain words, never ask him to run commands, and test before pushing.

## What it does
- **Cost calculator** (was “Costings”; data still `jobs`): manufacturing cost vs quoted price per order, worked out from saved rates (paper, mill board, printing, lamination, foiling, spot UV, die cutting, accessories, making).
- **Job cards**: internal instructions per order, with a master sheet and one sheet per team (designer, printing, fabrication, die, box making). PDF download. Every sheet starts with one strip: job card no. · date · client · product · qty (`sheetMeta`). The master sheet then opens with "First, discuss with the floor manager" (`discussPoints`, Raj's order): size, height difference (top & bottom only; `diff`, lid height = H − diff), board thickness (`boardThick`, else kappa board rows), half cut / grooving (`making`), inside paper printed (`inPrint` yes/no), coating & special effects, inserts — each with the decided value or a blank line + tick box, signed Floor manager / Job card made by / Date. The master sheet is one A4 page (Raj): floor-manager points, order details (order type, item, delivery due; no contact — Raj), Work order table (one line per team from `teamSummary` + its special note, blank Done by / Date to sign), materials, notes, sign-off; full team details/checklists stay on the team sheets. Every PDF sheet (master and each team) is one A4 page, so it's easy to hand out (Raj): drawn on a tall page, then cropped to A4 or shrunk to fit (`embedPage`). The "still missing" warning is screen-only (`screenOnly`). Designer sheet = 6 numbered steps with Done boxes (`{step:[n,title]}`), Raj's order: 1 share file with sales for client approval (blank version/dates row), 2 sheets with ups for printing, 3 dies for pastels and board (pastel die per pastel sheet, board die per kappa board row, other sheets 'Die'), 4 blocks for foiling/embossing/debossing, 5 positive for spot UV, 6 dies and plates for extras (accessories except magnets, inserts; tick/no. columns); steps with nothing show 'Not needed for this job.' The master's Work order row for the Designer lists the same six steps, one line each (multi-line cell; PDF `tw` measures the widest line). Printing team sheet (Raj): 1 colour approval — repeat job (`repeat` yes + `repeatOf` earlier job card no., set in the job card's Printing & paper section) matches the earlier job's colours, new job gets colours approved before full production (table per sheet: checked against / approved by / date & time); 2 print the sheets (paper, size, ups, colours + Pantone, sheets to print; total sheets + job qty); 3 count printed sheets (to print / printed / short) and pass to fabrication. Master Printing row lists the same. Die team sheet (Raj, `dieWork`): rigid + MDF — 1 cut the pastels to be pasted on board (pastel sheets; MDF: all printed sheets), 2 cut the board for grooving / half cut (kappa board rows; MDF: one MDF board row), 3 other printed items (e.g. booklet) if any; mono / corrugated — 1 cut the boxes (expected = sheets × ups via `upsNum`), 2 check creasing and pasting before the full quantity (checked by / date / remarks); printing jobs — cut the printed items. Pieces cut / boxes cut columns blank to fill. Master Die row lists the same. Repeat jobs (Raj): "Repeat this job" on a job card (`repeatCard`) makes a new card copying the spec, `repeat:'yes'`, `repeatOf`, and links back (`repeats` on the old card). Its form has "Repeat job: reuse or new?" (`reuseEditor`): artwork same/changed (+ what changed) and every tool from `toolsOf` — plates per sheet, pastel/sheet dies, board dies, blocks, spot UV positive, extras — Reuse old (default) / Correction (+ what) / Make new, stored in `c.reuse.tools[key]`. Team sheets add a Repeat job / Plates / Die / Block column (`toolText`: "Old die from CO-105", "Correction: …", "New plates"); designer skips client approval when the artwork is the same; die sheet warns when a die is corrected; master and designer show `repeatLine` at the top. No cost calculator changes (Raj said no). Finding job cards: list search "Find by job card no. or client name" (`cardMatches`: every word must match job card no. — with or without the dash —, client, item, box type), 50 rows at a time with "Show 50 more"; "+ New job card" has New job | Repeat an earlier job (search, top 15 results, Repeat button → `repeatCard`); the Earlier job card no. suggestions show the client.
- **Stock & procurement**: materials list; each job card takes its materials out of stock automatically (and puts them back when deleted); "To buy" list.

Each dispatch is a mix of variants; delivered / remaining per variant worked out from the dispatches. Rate per piece (same for all variants of a PO) in `poRates/<id>`, owner only. Owner + job cards role; only the owner deletes a PO. Parts of a PO can link to job cards (see Orders below). Same client with several open POs (different rates): a dispatch is split oldest PO first (PO date, then created) by variant name; each part saved on its PO with a shared `lot` id; edit/delete acts on the whole lot.

POs have **parts** (`o.parts` [{id, name, variants, cards}], Raj's example: box, 3 foams, 22 sleeve colours, envelopes, cards, manuals): variants can be pasted as a list (one "name qty" per line); each part links to 0..n job cards (a job card can serve several parts); rate per part in `poRates/<id>.parts` (owner only; older POs `rate`); `flattenParts` keeps `o.variants` (names "Part – variant" when several parts) so dispatches, invoices (`lineName`, `vRate`) and oldest-first splitting work unchanged; old POs read as one part (`partsOf`). **Delivery requests** (`o.requests` [{id, asked, needBy, urgent, note, items:{variantId:qty}, cancelled}]) instead of fixed phases: added whenever the client asks; a dispatch can be "against" one (`d.req`), which fills its quantities; "Rest of the PO" shows what nobody asked for yet. From a job card: "Add to order / PO" (`addToOrderPanel`) makes a new order from the job card (client, due, part = item, qty prefilled; PO no. optional — clients without a PO) or links it to a part of an open order / adds it as a new part (`linkCardToPart`, `addCardAsPart`); the job card header then shows the order button(s). An older PO's single `rate` applies only to its original part (`p1`), never to parts added later. No per-team status boxes (Raj removed them): parts just show their linked job card numbers; the running list shows a Job cards column. The same live running list is on the owner's Home screen, grouped by product (Raj): Rigid boxes, Mono cartons, Corrugated, MDF, Custom, Printing, No job card linked yet (`runningByGroup`, `RUN_GROUPS`): each part goes under the box type of its linked job card(s), so one PO can show in several groups (only those parts, their own % delivered, "+ N other parts"); a product fully delivered drops out; 5 rows per group + "See all". ## Where things are
- `web/firstbox.html` — **the whole page** (UI + logic, plain JS, no framework). Edit this file for almost every change.
  It is the same page that first ran inside Claude as an artifact, and still runs there unchanged.
- `web/firstbox-cloud.js` — makes the page work outside Claude: provides `window.claude.use('db' | 'user' | 'downloads')`
  on top of Supabase, plus the sign-in screen. Collections `team` and `requests` are mapped onto the `members` table.
- `web/index.html` — generated from `web/firstbox.html` by `python3 tools/make-index.py` (adds the script tags). Regenerate after editing; CI also regenerates it.
- `web/config.js` — Supabase project URL and publishable key (public by design; access is enforced by the database rules).
- `supabase/setup.sql` — tables `docs` (col, id, data jsonb) and `members` (role: owner / inventory / jobcards / pending / removed), row-level security, realtime. Re-runnable.
- `electron/` — the Mac/Windows app shell. Loads the online page (`electron/app-config.json` → `uiUrl`) when reachable, else the built-in `web/` copy. Saves PDFs in the **save folder** (default `Documents/Firstbox`; from v1.0.3 Raj can pick another with File › Change save folder… or the page's 📁 line, kept in `<userData>/firstbox-settings.json` `saveRoot`; a chosen folder that isn't there falls back to Documents/Firstbox): job cards → `Job cards/<job card no.>/`, proforma / tax invoice / delivery challan / payment receipt → `Invoices/`, sample sheets → `Samples/`, anything else → `Files/`. Preload exposes `getSaveFolder` / `chooseSaveFolder` / `resetSaveFolder` (trusted pages only); the page shows "📁 PDFs are saved in … · Change folder · Open folder · Use standard folder" on Billing, Job cards and Samples (`saveFolderBar`; older installs see a hint to update; browsers see nothing).
- `.github/workflows/build.yml` — push to `main` publishes the page (GitHub Pages; the repo is public since Nov 2026 so phones can open it); push a tag `vX.Y.Z` builds the Mac (.dmg) and Windows (.exe) installers into a GitHub release.

## Roles (enforced in `supabase/setup.sql`, mirrored in the page's `ROLES`; Raj's set, Nov 2026)
- owner: everything. The first account ever created becomes the owner (Raj, signs in with his email).
- admin: full control like the owner (SQL `is_admin()` = owner or admin; `firstbox-cloud.js` reports an admin as owner, so the page runs the owner branch). Can add/remove logins, but never change, remove or reset the owner, nor change their own role.
- Team logins are created by the owner or an admin on Settings › Team & access (username + password, shown once with "Copy for WhatsApp"; role list = `TEAM_ROLES` = `ROLES` + Admin).
  Behind the scenes a username is the Supabase login `<username>@firstbox.local`; SQL functions `create_member`,
  `set_member_password`, `delete_member` (owner/admin only) in `supabase/team-logins.sql`. Self sign-up is switched off in Supabase.

## Data model notes
- Everything the page stores is a JSON document at `collection/id` (e.g. `jobcards/CO-102`, `stock/<id>`, `config/defaults`).
- Job card numbers: series CO (complete order) / JW (job work); CO starts at 102.
- Calculation rules Raj gave (keep them): paper sheet cost = L × W (in) × GSM ÷ 1,550,000 × ₹/kg, 5 % wastage;
  mill board GSM = thickness × 660 grey / 680 white / 700 black; lamination kg = ΣL×W×sheets ÷ 1552 ÷ divisor (80 normal, 45 thermal, 30 velvet/anti-scratch), + 60 % labour;
  varnish L×W÷8 paise/sheet, hybrid ÷3.5; foil/emboss block ₹2000 + ₹0.70/up, min ₹4000; spot UV normal (Raj, Nov 2026): fixed ₹1000 + ₹1.50 a sheet for the first 1000 sheets (fewer sheets still charged as 1000) + ₹1 a sheet for every sheet after (`uvSlab`, `snapUv`, line `uvR1`/`uvR2`, settings `spotuv` {setup, r1, r2}, set only in Settings › Rate list "Spot UV rates" card (`uvRatesCard`, not on the cost sheet — Raj); "Use latest rates" re-snaps; older costings keep their old amount until the type is picked again), crystal (Raj): fixed ₹1000 + ₹2000 for the first 1000 sheets (₹2 a sheet) + ₹2.50 a sheet after (`uvCrystal`, settings `spotuvCrystal`);
  die ₹1500 each + cutting ₹1000 first 1000 sheets (Raj, Nov 2026; was ₹1200 — a saved table still at 1200 without `v:2` reads as 1000), ₹800 per further 1000 (on all printed sheets); magnets 2 per box if W > 170 mm else 1.
- Calculators (Raj, Nov 2026): "Finishing" is now **Coating** (coating line only) and **Special effects** is its own calculator right after it (`PARTS.fx`; `partOf` puts every `l.fx` line there, older costings included; added to every product's list).
- Mono cartons (Raj): calculators Printing & paper → Coating → Special effects → Die → Fabrication → Packaging & forwarding (numbered 1–6; `partNum` follows `partsFor`). Papers SBS / Art card / Duplex / Imported paper / Imported kraft; sheet cost (L×W×GSM÷3100 × ₹/kg ÷ 500) = same as the L×W×GSM÷1,550,000 rule; sheets = qty ÷ ups + wastage %; no pastels. Printing, coating, finishes, die same as rigid.
  Printing lines: “Pantone colour?” yes/no (`pms`), number of Pantones (`pmsCount`, 1–4) and code (`pantone`). Each Pantone is one more colour for plates and the printing rate (2 colours + 1 Pantone = priced as 3 colours), plus Pantone ink ₹1,500/kg, 1 kg per 3,000 sheets, part kg charged (sheets ÷ 3,000, 2 decimals) (`pmsInk`/`pmsSheets`, defaults in settings `pmsInkRate`/`pmsInkSheets`). Job card sheets carry `pms` and show “2 colour + 1 Pantone”.
  Printed sheets are called “Printed item” (name field: one name or “Lid + Base”; default names “Printed item N” are treated as unnamed). Non-rigid printed items can carry variants on one sheet (`l.vars` [{name, qty, ups}]): sheets = max(qty ÷ ups) + wastage, job qty = total of the variants (when one item has them), the rest are extras; rigid boxes keep pastels.
- Corrugated boxes: same calculators as mono plus “Corrugation” (the board part) between Special effects and Die. Board line (`corr:true`): ply 3/5/7, flute (3 ply B/C/E/A/F; 5 ply BC/EB/EE/BB/CC; 7 ply BCB/EBC/BBC), liner + fluting paper GSM → board GSM = liners × liner GSM + Σ fluting GSM × take-up (A 1.50, C 1.45, B 1.35, E 1.25, F 1.20); cost by weight × ₹/kg (typed per job until a corrugated rate is in the rate list). Costing asks “Type of box” (`boxStyle`: mailer / peti / handle / custom + `boxStyleNote`; older `corrStyle` still read). Making charges no longer used for corrugated.
- MDF boxes: calculators Printing & paper → Coating → Special effects → Inserts → Accessories (adds Handle with colour/type, Magnets) → Die → Fabrication (= making charges per box) → MDF board (last; `calc:'mdf'`, typed fresh every costing from the vendor: per box × qty or total for the job, + vendor/details). Costing asks “Type of MDF box” (`boxStyle`: tb / magnetic / custom + notes). `BOX_STYLES` holds the options for corrugated and MDF.
  Fabrication line (`calc:'fab'`): side pasting always ₹300 per 1000 cartons, Euro slot / Window pasting / Manual neck pasting (Raj; `neck`, `neckRate`, settings `neckPastePer1000`) optional (tick boxes only on the cost sheet, 2 × 2 — Raj: no rates shown there; rates per 1000 set in Settings › Rate list › "Fabrication rates" card (`fabRatesCard`, `FAB_OPTS`, `fabRate` = settings key ?? rate-list entry by name ?? default), "Use latest rates" re-snaps via `snapFab`). Packaging line (`calc:'pack'`): in sheet ₹10 per 2000 pcs (part 2000 = full) or in carton: ceil(qty/1000) × ₹ per carton.

## Making a change
1. Edit `web/firstbox.html` (and `firstbox-cloud.js` only for data/login behaviour). The page is one big script: a second top-level `const` with an existing name (e.g. `sizeIn`) breaks the whole page — check with `node --check` on the extracted script before testing.
2. `python3 tools/make-index.py`
3. Test in a browser with a fake Supabase (see `tools/` notes) or against the real project.
4. Commit and push to `main` → page updates online for everyone.
5. The repo is public, so a push to `main` updates the online page, and the installed Mac/Windows apps load that page:
   page changes need no new installers. Only when `electron/` changes (or Raj asks for a new version): bump `version` in `package.json`, push to `main`,
   then run the workflow with publish ticked: `gh workflow run build.yml --ref main -f publish=true`
   (pushing tags from Claude sessions may be refused). The release appears under Releases.
6. Database rule changes: update `supabase/setup.sql` and give Raj the SQL to paste into Supabase › SQL Editor.
