# Firstbox app

Internal software for Firstbox (custom rigid boxes, mono cartons, printing). Owner: Raj Wadhwa, who is not a programmer:
explain changes in plain words, never ask him to run commands, and test before pushing.

## What it does
- **Cost calculator** (was “Costings”; data still `jobs`): manufacturing cost vs quoted price per order, worked out from saved rates (paper, mill board, printing, lamination, foiling, spot UV, die cutting, accessories, making).
- **Job cards**: internal instructions per order, with a master sheet and one sheet per team (designer, printing, fabrication, die, box making). PDF download. Every sheet starts with one strip: job card no. · date · client · product · qty (`sheetMeta`). The master sheet then opens with "First, discuss with the floor manager" (`discussPoints`, Raj's order): size, height difference (top & bottom only; `diff`, lid height = H − diff), board thickness (`boardThick`, else kappa board rows), half cut / grooving (`making`), inside paper printed (`inPrint` yes/no), coating & special effects, inserts — each with the decided value or a blank line + tick box, signed Floor manager / Job card made by / Date. The master sheet is one A4 page (Raj): floor-manager points, order details (order type, item, delivery due; no contact — Raj), Work order table (one line per team from `teamSummary` + its special note, blank Done by / Date to sign), materials, notes, sign-off; full team details/checklists stay on the team sheets. The PDF draws the master on a tall page, then crops it to A4 or shrinks it to fit (`embedPage`). The "still missing" warning is screen-only (`screenOnly`). Designer sheet = 6 numbered steps with Done boxes (`{step:[n,title]}`), Raj's order: 1 share file with sales for client approval (blank version/dates row), 2 sheets with ups for printing, 3 dies for pastels and board (pastel die per pastel sheet, board die per kappa board row, other sheets 'Die'), 4 blocks for foiling/embossing/debossing, 5 positive for spot UV, 6 dies and plates for extras (accessories except magnets, inserts; tick/no. columns); steps with nothing show 'Not needed for this job.' The master's Work order row for the Designer lists the same six steps, one line each (multi-line cell; PDF `tw` measures the widest line).
- **Stock & procurement**: materials list; each job card takes its materials out of stock automatically (and puts them back when deleted); "To buy" list.
- **Database** (owner only): boxes made before with selling prices; search by size (L/W swap allowed, tolerance). Entries = `pastwork/<id>` (imported from Raj's old Excel sheet or added by hand) + every costing with a quoted price (live). Separate databases per product (Rigid boxes, Mono cartons, Corrugated boxes, MDF boxes; no printing; `cat` field, or from box type) — a costing only compares like with like. Search by size or by area (L × W sq in ± tolerance, like Raj's old Excel). Old Excel rows imported as `pastwork/old-NNNN` (source 'import', sizes converted from inches). Costing screen shows "Made before: N similar …".
- **Orders & dispatch**: client POs (`orders/<id>`: client, PO no., date, item, variants `[{id,name,qty}]`, dispatches `[{id,date,ref,note,items:{variantId:qty},by}]`). Each dispatch is a mix of variants; delivered / remaining per variant worked out from the dispatches. Rate per piece (same for all variants of a PO) in `poRates/<id>`, owner only. Owner + job cards role; only the owner deletes a PO. Not linked to job cards (Raj's choice). Same client with several open POs (different rates): a dispatch is split oldest PO first (PO date, then created) by variant name; each part saved on its PO with a shared `lot` id; edit/delete acts on the whole lot.
- **Sales & invoices** (was “Invoices”): four sections Proforma invoices | Tax invoices | Delivery challans | Payment receipts (+ Saved items link). `invoices/<id>` with type proforma / invoice / challan (challan: no prices, Consignor/Consignee, total qty, signature lines; made from a tax invoice or a dispatch lot). Payments `payments/<id>` (no RCPT-, date, client, amount, tds, mode, ref, bank, kind advance / full (shown as Balance clearance) / part, billId; form order: payment against, amount, type, mode, UPI → account no. (upiAcc), notes); a tax invoice counts payments on itself and on the proforma it came from; Payments panel on proforma/invoice; receipt PDF + “Copy for WhatsApp” / wa.me link. Numbering prefixes/next nos for all four in Billing details; period filter on all four lists (this month, last month, last 3 months, this / last financial year Apr–Mar, all time, custom from–to; default this month) drives the lists and KPIs; editor laid out like Refrens (Raj's screenshots) in Firstbox orange; no Billed By on screen (constant, from ⚙ Billing details = `shared/billing`, owner writes). Billed To: pick from client book `clients/<id>` or add new; GSTIN fills state + PAN (checksum checked) and, when set up, fetches name/address via RPC `gst_lookup` (supabase/gst-lookup.sql: Postgres `http` extension → AppyFlow verifyGST; key in `app_secrets`, owner sets it from Billing details; `window.firstboxGst` in firstbox-cloud.js). Items: proforma shows qty + rate only (no HSN/SAC or Unit, Raj's choice; values still kept for the tax invoice); tax invoice shows HSN/SAC, qty, unit, rate; GST fixed per settings (5 %). Saved items `billItems/<id>` (name, hsn, unit, last rate, size, savedAt/updatedAt) fill in when the name is picked again. Terms / payment terms edited one line each, separate standard text for proforma and invoice. Tax invoices: Shipped To (`ship`: on, same-as-billed-to or own address) and Transport Details (`transport`: transporter name + ID (GSTIN/TRANSIN), mode, vehicle, LR no./date, e-way bill, distance); transporters saved in `clients` with kind 'transporter' (kept out of client lists). PDF header shows Place of Supply and E-Way Bill No. PDF drawn with pdf-lib in Refrens layout, orange (₹ drawn as a path). IGST if client state ≠ Firstbox state, else CGST+SGST. Proforma → “Make tax invoice from this”. From Orders: “Make proforma” on a PO, “Make invoice” on a dispatch lot. Owner + job cards; only owner deletes. PO rates are owner-only, so job cards' invoices from a dispatch have blank rates.
- **Home** (owner): big logo, greeting, tiles. Staff land straight on their section.
- **Phones** (Raj's ask): same page, online at https://raj-firstbox.github.io/firstbox-app/ — open in Safari/Chrome and "Add to Home Screen" (manifest + icons in `web/manifest.webmanifest`, `web/icons/`, tags added by make-index.py; no service worker on purpose, so nobody gets a stale cached page). At ≤640 px: section tabs become a bottom bar with icons + short names (hidden while typing), `table.jobs` lists turn into cards (cells labelled from the header by `labelListRows`), KPIs 2-up, inputs 16 px (no iPhone zoom). Check new screens at 360/390/412 px wide; a wide element (even a hidden `.sr` label) widens the whole phone page.
- **Settings ⚙**: Rate list, Price history, Billing details, Team & access.
- **Save button** (Raj): editing pages (`MANUAL`: costing, job card, proforma/invoice/challan, payment receipt, rate list, billing details) write nothing until Save (top button row + bar at the bottom, ⌘S/Ctrl+S). Their writes go through `pageSave` into `ED.q`; `saveAll` flushes them (then job card stock sync); leaving via `go()` or the browser back button with unsaved changes shows "Save your changes?" (Save and continue / Don't save / Stay); Don't save puts the page's data back from `ED.restore` (`makeRestore`, taken when the page opens or after a save). Actions that open another page (create job card, convert to tax invoice, make challan, record payment) save first. Lines the app adds by itself when a costing opens save straight away (`touchAuto`). Closing the tab asks via beforeunload; the desktop app shows its own dialog (`will-prevent-unload` in electron/main.js, `confirmsUnload` in preload) from the next installer on — older installs close without asking. Other pages (orders, stock, team, database) already save when their form's button is pressed.

## Where things are
- `web/firstbox.html` — **the whole page** (UI + logic, plain JS, no framework). Edit this file for almost every change.
  It is the same page that first ran inside Claude as an artifact, and still runs there unchanged.
- `web/firstbox-cloud.js` — makes the page work outside Claude: provides `window.claude.use('db' | 'user' | 'downloads')`
  on top of Supabase, plus the sign-in screen. Collections `team` and `requests` are mapped onto the `members` table.
- `web/index.html` — generated from `web/firstbox.html` by `python3 tools/make-index.py` (adds the script tags). Regenerate after editing; CI also regenerates it.
- `web/config.js` — Supabase project URL and publishable key (public by design; access is enforced by the database rules).
- `supabase/setup.sql` — tables `docs` (col, id, data jsonb) and `members` (role: owner / inventory / jobcards / pending / removed), row-level security, realtime. Re-runnable.
- `electron/` — the Mac/Windows app shell. Loads the online page (`electron/app-config.json` → `uiUrl`) when reachable, else the built-in `web/` copy. Saves PDFs to `Documents/Firstbox/Job cards/<job card no.>/` (invoices to `Documents/Firstbox/Invoices/`).
- `.github/workflows/build.yml` — push to `main` publishes the page (GitHub Pages; the repo is public since Nov 2026 so phones can open it); push a tag `vX.Y.Z` builds the Mac (.dmg) and Windows (.exe) installers into a GitHub release.

## Roles (enforced in `supabase/setup.sql`, mirrored in the page's `ROLES`)
- owner: everything. The first account ever created becomes the owner (Raj, signs in with his email).
- Team logins are created by the owner on ⚙ › Team & access (username + password, shown once with "Copy for WhatsApp").
  Behind the scenes a username is the Supabase login `<username>@firstbox.local`; SQL functions `create_member`,
  `set_member_password`, `delete_member` (owner only) in `supabase/team-logins.sql`. Self sign-up is switched off in Supabase.
- inventory: reads job cards/stock, writes stock + stockLog only.
- jobcards: reads/writes job cards, stock, stockLog, orders, invoices, clients, billItems, payments; can use gst_lookup. Cannot delete job cards, POs or invoices.
- Costings (`jobs`), `rates`, `rateHistory`, `config`, `poRates`, `pastwork`: owner only. `shared/lists` (paper names, lamination divisors): owner writes, staff read.

## Data model notes
- Everything the page stores is a JSON document at `collection/id` (e.g. `jobcards/CO-102`, `stock/<id>`, `config/defaults`).
- Job card numbers: series CO (complete order) / JW (job work); CO starts at 102.
- Calculation rules Raj gave (keep them): paper sheet cost = L × W (in) × GSM ÷ 1,550,000 × ₹/kg, 5 % wastage;
  mill board GSM = thickness × 660 grey / 680 white / 700 black; lamination kg = ΣL×W×sheets ÷ 1552 ÷ divisor (80 normal, 45 thermal, 30 velvet/anti-scratch), + 60 % labour;
  varnish L×W÷8 paise/sheet, hybrid ÷3.5; foil/emboss block ₹2000 + ₹0.70/up, min ₹4000; spot UV ₹1.50 / ₹3 crystal per sheet + ₹1000 positive;
  die ₹1500 each + cutting ₹1200 first 1000 sheets, ₹800 per further 1000 (on all printed sheets); magnets 2 per box if W > 170 mm else 1.
- Mono cartons (Raj): calculators Printing & paper → Finishing → Die → Fabrication → Packaging & forwarding (numbered 1–5; `partNum` follows `partsFor`). Papers SBS / Art card / Duplex / Imported paper / Imported kraft; sheet cost (L×W×GSM÷3100 × ₹/kg ÷ 500) = same as the L×W×GSM÷1,550,000 rule; sheets = qty ÷ ups + wastage %; no pastels. Printing, coating, finishes, die same as rigid.
  Printing lines: “Pantone colour?” yes/no (`pms`), number of Pantones (`pmsCount`, 1–4) and code (`pantone`). Each Pantone is one more colour for plates and the printing rate (2 colours + 1 Pantone = priced as 3 colours), plus Pantone ink ₹1,500/kg, 1 kg per 3,000 sheets, part kg charged (sheets ÷ 3,000, 2 decimals) (`pmsInk`/`pmsSheets`, defaults in settings `pmsInkRate`/`pmsInkSheets`). Job card sheets carry `pms` and show “2 colour + 1 Pantone”.
  Printed sheets are called “Printed item” (name field: one name or “Lid + Base”; default names “Printed item N” are treated as unnamed). Non-rigid printed items can carry variants on one sheet (`l.vars` [{name, qty, ups}]): sheets = max(qty ÷ ups) + wastage, job qty = total of the variants (when one item has them), the rest are extras; rigid boxes keep pastels.
- Corrugated boxes: same calculators as mono plus “Corrugation” (the board part) between Finishing and Die. Board line (`corr:true`): ply 3/5/7, flute (3 ply B/C/E/A/F; 5 ply BC/EB/EE/BB/CC; 7 ply BCB/EBC/BBC), liner + fluting paper GSM → board GSM = liners × liner GSM + Σ fluting GSM × take-up (A 1.50, C 1.45, B 1.35, E 1.25, F 1.20); cost by weight × ₹/kg (typed per job until a corrugated rate is in the rate list). Costing asks “Type of box” (`boxStyle`: mailer / peti / handle / custom + `boxStyleNote`; older `corrStyle` still read). Making charges no longer used for corrugated.
- MDF boxes: calculators Printing & paper → Finishing → Inserts → Accessories (adds Handle with colour/type, Magnets) → Die → Fabrication (= making charges per box) → MDF board (last; `calc:'mdf'`, typed fresh every costing from the vendor: per box × qty or total for the job, + vendor/details). Costing asks “Type of MDF box” (`boxStyle`: tb / magnetic / custom + notes). `BOX_STYLES` holds the options for corrugated and MDF.
  Fabrication line (`calc:'fab'`): side pasting always ₹300 per 1000 cartons, Euro slot / Window pasting optional (rates per 1000 from the rate list by name, else last typed, kept in settings). Packaging line (`calc:'pack'`): in sheet ₹10 per 2000 pcs (part 2000 = full) or in carton: ceil(qty/1000) × ₹ per carton.

## Making a change
1. Edit `web/firstbox.html` (and `firstbox-cloud.js` only for data/login behaviour).
2. `python3 tools/make-index.py`
3. Test in a browser with a fake Supabase (see `tools/` notes) or against the real project.
4. Commit and push to `main` → page updates online for everyone.
5. The repo is public, so a push to `main` updates the online page, and the installed Mac/Windows apps load that page:
   page changes need no new installers. Only when `electron/` changes (or Raj asks for a new version): bump `version` in `package.json`, push to `main`,
   then run the workflow with publish ticked: `gh workflow run build.yml --ref main -f publish=true`
   (pushing tags from Claude sessions may be refused). The release appears under Releases.
6. Database rule changes: update `supabase/setup.sql` and give Raj the SQL to paste into Supabase › SQL Editor.
